\section{Training Setup}

\subsection{Shared Configuration}

The following hyperparameters and settings are shared across all three experiments:

\begin{itemize}
    \item \textbf{Optimizer:} AdamW \cite{loshchilov2019adamw}
    \item \textbf{Loss function:} \texttt{nn.CrossEntropyLoss} (no class weighting)
    \item \textbf{Gradient clipping:} Maximum gradient norm of 1.0 (applied before every optimizer step)
    \item \textbf{Early stopping:} Patience of 3 epochs; triggered when validation macro-F1 does not improve
    \item \textbf{Checkpoint criterion:} Best model saved when validation macro-F1 is strictly higher than the previous best
    \item \textbf{Random seed:} 42 (set for \texttt{random}, \texttt{numpy}, \texttt{torch}, \texttt{torch.cuda})
    \item \textbf{Hardware:} NVIDIA GeForce RTX 4060 Laptop GPU (8 GB VRAM)
    \item \textbf{Precision:} Float32 (no mixed precision)
\end{itemize}

\subsection{Learning Rate Scheduler}

For EXP-1, the learning rate is held constant throughout training. For EXP-2 and EXP-3, a linear warm-up and linear decay schedule is used. During the first 10\% of total training steps, the learning rate increases linearly from 0 to the peak value; for the remaining 90\% of steps, it decays linearly back to 0. This schedule is provided by HuggingFace \texttt{transformers.get\_linear\_schedule\_with\_warmup}.

\subsection{DataLoaders}

All datasets are loaded using \texttt{torch.utils.data.DataLoader}. The \texttt{DataCollatorWithPadding} collate function is used to dynamically pad sequences to the per-batch maximum length. EXP-1 receives token IDs and attention masks (lengths are derived from masks); EXP-2 and EXP-3 receive token IDs and attention masks and pass both to the DistilBERT backbone.

\subsection{Model Saving and Loading}

At the end of each epoch, if the current validation macro-F1 exceeds the best previously recorded value, the model state dict is saved to disk (e.g.\ \path{outputs/checkpoints/bilstm_best.pt}). After training completes (by reaching max epochs or early stopping), the best checkpoint is loaded and used for final test evaluation.
